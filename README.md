# آکادمی هوش مصنوعی (AI Academy)

پلتفرم آموزشی فارسی (راست‌به‌چپ): دوره بسازید، محتوای هر درس را با هوش مصنوعی تولید و ویرایش کنید، با معلم هوشمند گفتگو کنید و پیشرفت‌تان را ببینید.

> **وضعیت فنی:** ساخت فرانت‌اند، بررسی TypeScript بک‌اند و ۵۰ آزمون Worker در GitHub Actions با موفقیت اجرا شده‌اند. اتصال واقعی به حساب OpenRouter و استقرار واقعی Cloudflare هنوز نیازمند تنظیم کلیدها و حساب مالک پروژه است؛ این موارد را نباید با تست خودکار اشتباه گرفت.

## چه کارهایی می‌کند
- ساخت، ویرایش (فصل‌ها و درس‌ها)، حذف و جست‌وجوی دوره‌ها؛ سطح مبتدی/متوسط/پیشرفته
- طراحی خودکار فصل‌ها و درس‌ها با AI
- تولید محتوای درس با AI (مقدمه، اهداف، آموزش، مثال، نکته، تمرین، آزمون، جمع‌بندی)، ذخیره، ویرایش و تولید مجدد
- بررسی پاسخ تمرین با AI؛ آزمون چندگزینه‌ای با تصحیح خودکار
- معلم هوشمند: گفتگو درباره هر موضوع یا همان درس، با حفظ تاریخچه
- ذخیره پیشرفت، «ادامه از آخرین درس»، امتیاز (XP)، سطح و هدف روزانه
- پروفایل، پشتیبان‌گیری JSON، نصب به‌صورت PWA، کار آفلاین برای درس‌های ذخیره‌شده

## قابلیت‌های آموزشی و محدودیت‌های فعلی
- بازی آموزشی مبتنی بر سؤال‌های درس، امتیاز، زنجیره پاسخ درست و ذخیره ۲۰ نتیجه آخر روی همان دستگاه
- آزمون تجمیعی از سؤال‌های درس‌ها، تصحیح خودکار، توضیح پاسخ و ذخیره ۲۰ نتیجه آخر روی همان دستگاه
- داشبورد پیشرفت شامل تکمیل درس‌ها، XP، سطح، نشان‌ها و خلاصه بهترین نتیجه آزمون و بازی

زیرساخت ثبت‌نام و ورود بدون رمز با کد ایمیل، نشست‌های ابری و API همگام‌سازی اختصاصی هر کاربر اکنون در Worker پیاده‌سازی شده است. **قابلیت عملیاتی شدن آن هنوز به ساخت D1، اتصال binding و تنظیم سرویس ایمیل Resend نیاز دارد**؛ تا انجام این تنظیمات، ساخت حساب و همگام‌سازی در نسخه منتشرشده فعال نخواهد بود. جست‌وجوی زنده وب و آداپتور Gemini نیز هنوز فعال نیست. جزئیات امنیت و استقرار در SECURITY.md.

## اجرای محلی
نیاز: Node.js نسخه ۲۰.۱۹ یا بالاتر.

فرانت‌اند:
```
cd frontend
npm ci
npm run build
npm run dev
```

Worker:
```
cd worker
npm install
npm run typecheck
npm test
```

فایل قفل وابستگی فرانت‌اند (`frontend/package-lock.json`) در مخزن نگهداری می‌شود. برای Worker فعلاً از `npm install` استفاده می‌شود.

## راهنمای استقرار

### GitHub Pages
در مخزن، از مسیر **Settings ← Pages**، گزینه **GitHub Actions** را به‌عنوان منبع انتشار انتخاب کنید. گردش‌کار `Deploy frontend to GitHub Pages` بعد از ادغام کد روی شاخه `main` اجرا می‌شود.

### Worker (بک‌اند)
1. در Cloudflare حساب بسازید و از پوشه `worker` اجرا کنید:
   ```
   npm install
   npx wrangler login
   ```
2. در `worker/wrangler.toml` مقدار `ALLOWED_ORIGIN` را با مبدأ واقعی GitHub Pages جایگزین کنید؛ فقط دامنه، بدون مسیر مخزن و بدون اسلش پایانی.
3. کلید هوش مصنوعی را به‌صورت Secret در Cloudflare ثبت کنید:
   ```
   npx wrangler secret put OPENROUTER_API_KEY
   ```
   `ACCESS_TOKEN` فقط برای سازگاری موقت با نسخه‌های قدیمی لازم است؛ نسخه حساب‌محور جدید از نشست اختصاصی کاربر استفاده می‌کند. هیچ‌کدام از Secretها را در فایل‌ها یا مخزن GitHub قرار ندهید.
4. استقرار:
   ```
   npx wrangler deploy
   ```
5. پس از فعال‌سازی D1 و ایمیل، کاربران از صفحه ورود با ایمیل حساب می‌سازند؛ نیازی به توکن مشترک در تنظیمات برنامه نیست.



### استقرار خودکار Worker از GitHub Actions

گردش‌کار `.github/workflows/deploy-worker.yml` اضافه شده است. برای فعال‌کردن آن، فقط یک‌بار در تنظیمات مخزن از مسیر **Settings → Secrets and variables → Actions → New repository secret** این دو Secret را بسازید:

- `CLOUDFLARE_API_TOKEN`: توکن API کلادفلر با مجوزهای لازم برای استقرار Worker در همان حساب.
- `CLOUDFLARE_ACCOUNT_ID`: شناسه حساب Cloudflare.

پس از ثبت این دو Secret، گردش‌کار با هر تغییر در پوشه `worker/` ابتدا آزمون‌ها و TypeScript را اجرا می‌کند و فقط در صورت موفقیت، Worker را منتشر می‌کند. همچنین می‌توانید آن را از زبانه **Actions → Deploy Cloudflare Worker → Run workflow** دستی اجرا کنید. مقدارهای Secret را در گفتگو، کد یا فایل مخزن قرار ندهید.

### راه‌اندازی حساب کاربری و پایگاه داده ابری

API ثبت‌نام/ورود با کد یک‌بارمصرف ایمیل، اعتبارسنجی نشست، خروج از حساب و همگام‌سازی دوره‌ها و گفتگوها در Worker پیاده‌سازی شده است. طرح SQL مربوط به کاربران، کدهای تأیید، نشست‌ها و داده‌های اختصاصی کاربران در worker/migrations/0001_auth_and_sync.sql قرار دارد. این قابلیت‌ها تا زمان انجام تنظیمات زیر روی سایت فعال نمی‌شوند.

برای مرحله راه‌اندازی، مالک پروژه باید در پوشه worker یک D1 بسازد:

```bash
npx wrangler d1 create ai-academy-db
```

سپس شناسه دیتابیس خروجی Cloudflare باید در یک binding با نام DB در worker/wrangler.toml قرار بگیرد (شناسه دیتابیس عمومی است، اما نباید مقدار ساختگی گذاشت). در فایل `worker/wrangler.toml` بلوک `[[d1_databases]]` را از حالت توضیح خارج کنید و `database_id` واقعی خروجی دستور را قرار دهید. سپس migration را اعمال کنید:

```bash
npx wrangler d1 migrations apply ai-academy-db --remote
```

**این migration هنوز روی هیچ دیتابیس ابری اجرا نشده است.** سپس در پوشه `worker` این Secretها را تنظیم کنید (فرستنده باید در Resend تأیید شده باشد):

```bash
npx wrangler secret put RESEND_API_KEY
npx wrangler secret put EMAIL_FROM
npx wrangler secret put AUTH_PEPPER
```

`EMAIL_FROM` نمونه: `AI Academy <login@example.com>`. برای ساخت `AUTH_PEPPER` می‌توانید از `openssl rand -hex 32` استفاده کنید؛ مقدار آن را در گفتگو یا مخزن قرار ندهید. پس از تنظیم binding و Secretها، Worker را دوباره deploy کنید. کدهای ایمیل ۱۰ دقیقه اعتبار دارند، تعداد تلاش‌ها محدود است و فقط هش کد و نشست در D1 ذخیره می‌شود. نشست‌ها قابل ابطال هستند و داده‌های دوره/گفتگو با شناسه کاربر محدود می‌شوند. هیچ توکن مشترکی هویت حساب کاربر نیست.

### نکات هزینه و ایمنی
- هر تولید درس یا گفت‌وگو ممکن است توکن مصرف کند؛ برای کلید OpenRouter سقف هزینه تنظیم کنید.
- نشست حساب کاربری مجوز دسترسی به داده‌های همان کاربر است. پشتیبانی از توکن مشترک فقط برای نسخه‌های قدیمی باقی مانده و باید پس از مهاجرت حذف شود.
- کلید OpenRouter فقط باید در Secretهای Worker ذخیره شود و نباید به فرانت‌اند برسد.

## ساختار پروژه
- `frontend/` برنامه React؛ `database/` (IndexedDB)، `services/`، `pages/` و `components/`
- `worker/` بک‌اند: `providers/`، `agents/` و `security/`
- `worker/test/` آزمون‌های خودکار Worker
